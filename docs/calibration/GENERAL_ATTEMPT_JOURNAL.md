# General plan attempt journal, Step 4.2 candidate

Reuses PlanStore, TaskQueue, existing task IDs and SQLite. A task_attempts table adds per-attempt evidence; it does not add a new executor, task type, Adult bridge, provider call or daemon. General plan tasks remain workspace_status, memory_recent and explicitly configured local_code_report.

Each targeted claim atomically increments the queue attempt and records task/step/attempt identity, claim stamp, start time, method and canonical input fingerprints. Queue finish and journal finish commit together with the same claim fence. A success records a SHA-256 of the existing stored result, not a second copy. A failure records a fixed classification/code and retryability, not raw exception text in the journal. Existing queue/plan last_error retention is unchanged.

Method identity is an explicit workspace-readonly-v1 operation name, not a hash of implementation files. Input identity is the canonical task payload, not the source files, current memory database or environment. Fingerprints identify repeated requests; they are not encryption or proof that an environment did not change. Low-entropy payload hashes may be guessable.

PermissionError and fixed code-context scope/config errors are permission failures. Timeouts/connection failures are transient; storage repair, invalid input/state and unknown failures are distinct and never assumed retryable. This classification is evidence, not permission to retry. No error text is interpreted as owner consent, and changing an error string does not change filesystem scope.

Known failures still pause at once. A later dispatch requires the existing explicit retry action. That action now records a bounded retry reason, default explicit_retry_requested for compatible existing callers. It does not claim the operator actually repaired anything. A more specific reason can be supplied, but is an assertion, not measured proof. The same method/input can legitimately succeed after an external permission or state repair, so explicit retry does not invent a different fingerprint or get blocked merely because bytes match. Automatic repeated dispatch, completed replay and unknown-running replay remain refused by targeted claims and lifecycle checks. Cross-task duplicate requests can represent separate authorized work; this journal does not collapse them or promise global deduplication.

The journal covers attempts created after migration. Legacy completed results remain unchanged and do not receive invented history. Legacy interrupted claims retain their original fencing behavior. Backup/restore accepts both the former three-table schema and the additive journal schema, validates journal identity/fingerprints/lifecycle/result association and copies journal data privately. Existing no-init HTTP cancellation accepts either exact schema without migrating it. No attempt-history HTTP endpoint is added. Authorized local callers can use list_plan_attempts; its metadata still belongs to the private task store.

Acceptance journey: real SQLite and the production deterministic workspace_status worker, forced permission failure, no automatic repeat while paused, explicit recorded repair/retry, close/reopen, success with unchanged method/input identity, second attempt retained alongside first, completed reopen does not dispatch, private backup/restore preserves history and result digest. Separate tests cover transient vs permission classification, stale claim rollback and old-schema no-mutation backup. Model responses are synthetic only where existing Adult tests require them; this candidate makes no live-model claim.

Limits: no new alternative-model/tool selection is added. Existing general operations are deterministic and fixed. The journal distinguishes operation and input choices but cannot make an unsupported general task executable. No five-failure supervisor or whole Step 4.3 acceptance is claimed. This is a Step 4.2 candidate for exact written-criterion review, not automatic acceptance or release readiness.

## Nonretryable blocker gate
The retry transition consults the latest durable attempt inside the same immediate transaction. A journaled nonretryable failure refuses the default or blank reason before any queue/plan/journal update. RetryBlockedError is a ValueError subtype. A specific bounded reason permits an explicit retry and is retained as an UNVERIFIED operator assertion, never proof that the source or environment changed. A repeated nonretryable failure blocks the next default retry again. Transient failures and legacy failed tasks with no journal row preserve the default explicit retry call. No retry call dispatches work. MCP forwards the reason and surfaces the same refusal; subsequent authorized execution is still required.
