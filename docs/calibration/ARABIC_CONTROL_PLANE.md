# Arabic-first local dashboard presentation

The existing private dashboard now declares Arabic and RTL for its headings,
control labels, descriptions and input guidance. Plan/step IDs, code, JSON and
saved evidence use LTR text with isolated direction. Request text uses automatic
direction. Native machine status strings, result bodies, runtime errors and
confirmation dialogs remain in English in this first presentation slice, with
an Arabic state legend. It is not a complete locale system or an Arabic model
quality claim. Exact machine output is not translated or rewritten as evidence.

The two enqueue choices, their values, API routes, auth headers, token storage,
request fences, model and task dispatch behavior remain unchanged. Arabic text
explains the existing explicit enablement and separate enqueue/execute actions;
it does not grant authority, turn on a provider or run background work. The
free-route guard still owns the no-paid-fallback boundary.

Visual qualification uses a synthetic local source quote and real local HTTP,
normal monitoring unlock followed by saved-report read, at desktop and 390px.
No live provider or user-secret content is involved. Full Arabic empty/error/
confirmation coverage, accessibility audit and whole Stage 10 acceptance remain
unfinished.

The combined execution-result privacy warning is translated faithfully: changing
the token hides results but does not cancel submitted requests; inspect current
state before repeating an uncertain action. Generic action/model JS errors and
monitoring-refresh messages remain English under this partial-locale policy.
